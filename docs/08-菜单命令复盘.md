# 菜单命令复盘：从“为什么”到“怎么做”

> 日期：2026-11-09
> 项目：`com.example.hello`
> 环境：Eclipse 2026-06（4.40.0）+ Temurin JDK 21.0.13
> 结果：运行时 Eclipse 主菜单出现 `Hello > Say Hello`，点击弹出 `Hello from command handler!`，`Ctrl+Shift+Alt+H` 生效。

## 一、今天做成了什么

你完成了一条完整的“命令链路”：

```text
用户点击菜单 / 按快捷键
        │
        │ 通过 commandId 找到
        ▼
Command 定义（plugin.xml）
        │
        │ 绑定到
        ▼
Handler 类（SayHelloHandler）
        │
        │ 执行
        ▼
MessageDialog.openInformation(...)
```

最终效果：

- 主菜单最右边出现 `Hello > Say Hello`
- 点击菜单，弹出 `Hello from command handler!`
- `Ctrl+Shift+Alt+H` 也能触发
- `Preferences > General > Keys` 里能搜到 `Say Hello`

这不是“加了一个菜单项”这么简单。你实际走通了：

**扩展注册表 → 命令定义 → 处理器绑定 → 菜单贡献 → 快捷键绑定 → OSGi Bundle 解析 → 运行时实例加载。**

## 二、先建立一张总图

### 2.1 命令体系

```text
┌─────────────────────────────────────────────┐
│ 触发入口                                     │
│ 主菜单 / 工具栏 / 右键菜单 / 快捷键           │
└──────────────────┬──────────────────────────┘
                   │ commandId
                   ▼
┌─────────────────────────────────────────────┐
│ Command（命令）                              │
│ 只有 ID、名称、说明，没有代码                 │
│ 例如 com.example.hello.commands.sayHello     │
└──────────────────┬──────────────────────────┘
                   │ commandId
                   ▼
┌─────────────────────────────────────────────┐
│ Handler（处理器）                            │
│ 真正执行代码的类                              │
│ 例如 SayHelloHandler.execute(...)            │
└──────────────────┬──────────────────────────┘
                   ▼
              业务代码 / UI
```

### 2.2 OSGi 加载体系

```text
MANIFEST.MF
  │ 声明依赖、BREE、导出包
  ▼
OSGi 解析（resolve）
  │ 所有 Require-Bundle / Import-Package 都必须满足
  ▼
Bundle 变成 ACTIVE
  │
  ▼
扩展注册表读取 plugin.xml
  │ 注册命令、处理器、菜单、快捷键
  ▼
运行时 Eclipse 显示菜单 / 响应快捷键
```

这两张图合起来，就是今天所有问题的根源：

- 命令链路负责“点了以后执行什么”；
- OSGi 链路负责“这个插件能不能被加载、扩展能不能被注册”。

**只要 OSGi 解析失败，命令链路再正确也不会出现在界面上。**

## 三、为什么要加四个扩展点

`plugin.xml` 里新增了四段：

| 扩展点 | 角色 | 解决的问题 |
|---|---|---|
| `org.eclipse.ui.commands` | 定义命令 | 这个动作叫什么、ID 是什么 |
| `org.eclipse.ui.handlers` | 绑定处理器 | 这个动作由哪个 Java 类执行 |
| `org.eclipse.ui.menus` | 菜单贡献 | 这个动作出现在哪个菜单/工具栏 |
| `org.eclipse.ui.bindings` | 快捷键 | 这个动作绑定哪个键盘组合 |

为什么要拆成四段，而不是直接在菜单里写 Java 类？

因为 Eclipse 采用“声明式贡献 + 松耦合”：

1. **命令 ID 是契约**：菜单、工具栏、快捷键都只认 ID。
2. **一个命令可以有多个触发入口**：同一个 `sayHello` 可以同时出现在主菜单、工具栏、右键菜单、快捷键。
3. **处理器可以替换**：不同上下文可以给同一个命令绑定不同实现。
4. **可以启用/禁用**：通过 `enabledWhen` 或 `setEnabled` 控制命令是否可用。
5. **便于扩展**：其他插件可以给同一个命令增加菜单项或快捷键。

这就是“命令与实现分离”的价值。

## 四、`plugin.xml` 逐段解释

### 4.1 定义命令

```xml
<extension point="org.eclipse.ui.commands">
   <command
         id="com.example.hello.commands.sayHello"
         name="Say Hello"
         description="Show a hello message from the command handler.">
   </command>
</extension>
```

- `point`：告诉 Eclipse 这是对 `org.eclipse.ui.commands` 扩展点的贡献。
- `id`：命令唯一标识。后面三处必须完全一致。
- `name`：显示名称，会出现在 Preferences > Keys 等地方。
- `description`：说明文字。
- 这里**没有代码**，只是声明“存在这样一个命令”。

### 4.2 绑定处理器

```xml
<extension point="org.eclipse.ui.handlers">
   <handler
         commandId="com.example.hello.commands.sayHello"
         class="com.example.hello.handlers.SayHelloHandler">
   </handler>
</extension>
```

- `commandId`：和上面定义的 ID 完全一致。
- `class`：处理器全限定类名。
- Eclipse 在命令第一次执行时才实例化这个类（懒加载）。
- 如果类名写错，点击菜单时会在 `.metadata/.log` 里看到 `ClassNotFoundException` 或 `PartInitException`。

### 4.3 菜单贡献

```xml
<extension point="org.eclipse.ui.menus">
   <menuContribution
         locationURI="menu:org.eclipse.ui.main.menu?after=additions">
      <menu id="com.example.hello.menu.hello" label="Hello">
         <command
               commandId="com.example.hello.commands.sayHello"
               label="Say Hello"
               style="push">
         </command>
      </menu>
   </menuContribution>
</extension>
```

- `locationURI`：不是文件路径，而是“菜单位置 URI”。
  - `menu:` 表示菜单栏；
  - `org.eclipse.ui.main.menu` 是主菜单栏；
  - `?after=additions` 表示放在 `additions` 分组后面。
- `<menu>`：创建一个顶级菜单 `Hello`。
- `<command>`：在 `Hello` 菜单里放一个命令项。
- `style="push"`：普通按钮；还有 `toggle`（勾选）、`radio`（单选）。
- 菜单只引用 `commandId`，不直接引用 Java 类。

> 因为 `after=additions`，`Hello` 可能出现在菜单栏最右边，甚至在 `Help` 后面。找不到时先看最右边。

### 4.4 快捷键

```xml
<extension point="org.eclipse.ui.bindings">
   <key
         commandId="com.example.hello.commands.sayHello"
         schemeId="org.eclipse.ui.defaultAcceleratorConfiguration"
         sequence="M1+M2+M3+H">
   </key>
</extension>
```

- `schemeId`：快捷键方案，默认方案即可。
- `sequence`：按键组合。
  - `M1` = Ctrl（Windows/Linux）
  - `M2` = Shift
  - `M3` = Alt
  - `M4` = Command（macOS）
- `M1+M2+M3+H` = **Ctrl+Shift+Alt+H**。

> 不要用 `M1+M3+H`（Ctrl+Alt+H）。在 JDT 里它默认绑定到 `Open Call Hierarchy`，会把你的命令抢走。

## 五、`SayHelloHandler` 逐行解释

```java
package com.example.hello.handlers;

import org.eclipse.core.commands.AbstractHandler;
import org.eclipse.core.commands.ExecutionEvent;
import org.eclipse.core.commands.ExecutionException;
import org.eclipse.jface.dialogs.MessageDialog;
import org.eclipse.ui.handlers.HandlerUtil;

public class SayHelloHandler extends AbstractHandler {

    @Override
    public Object execute(ExecutionEvent event) throws ExecutionException {
        MessageDialog.openInformation(
                HandlerUtil.getActiveShell(event),
                "Hello Command",
                "Hello from command handler!");
        return null;
    }
}
```

逐行：

| 代码 | 含义 |
|---|---|
| `package com.example.hello.handlers;` | 处理器放在独立包，避免和视图类混在一起 |
| `AbstractHandler` | 3.x 命令处理器基类，提供 `execute`、`isEnabled` 等 |
| `ExecutionEvent` | 本次命令执行的上下文：触发源、当前选择、参数等 |
| `ExecutionException` | 执行失败时抛出，平台会记录到日志 |
| `MessageDialog` | JFace 的对话框工具类 |
| `HandlerUtil.getActiveShell(event)` | 从事件上下文里找当前活动窗口，作为对话框父窗口 |
| `openInformation(...)` | 打开信息对话框 |
| `return null;` | 命令没有返回值；大多数 UI 命令都返回 `null` |

关键点：

1. **没有 `main` 方法**。平台在命令触发时创建 `SayHelloHandler` 并调用 `execute`。
2. **Handler 通常是无状态的**。不要在里面长期保存 UI 控件引用；每次执行都可能是一个新实例。
3. **父窗口要从 `event` 里取**，不要自己 `new Shell()`。
4. **业务逻辑应该放在 Service 里**，Handler 只做“入口适配”。今天为了简单才直接弹对话框。

## 六、点击菜单后，到底发生了什么

时序：

1. 运行时 Eclipse 启动，OSGi 解析 `com.example.hello`。
2. 扩展注册表读取 `plugin.xml`，注册命令、处理器、菜单、快捷键。
3. 你在主菜单点击 `Hello > Say Hello`。
4. 平台根据菜单项上的 `commandId` 找到命令。
5. 平台根据 `org.eclipse.ui.handlers` 找到 `SayHelloHandler`。
6. 平台实例化处理器（如果还没实例化）。
7. 调用 `execute(ExecutionEvent)`。
8. `HandlerUtil.getActiveShell(event)` 拿到窗口。
9. `MessageDialog.openInformation(...)` 显示对话框。
10. `execute` 返回 `null`，平台继续事件循环。

这条链路说明：

- 菜单不“知道” Java 类；
- 命令不“知道”界面；
- 处理器不“知道”自己被哪个菜单触发；
- 三者通过 `commandId` 解耦。

## 七、故障复盘：为什么一开始没有 `Hello` 菜单

这是今天最有价值的部分。

### 7.1 现象

运行时 Eclipse 菜单栏只有：

```text
File Edit Navigate Search Project Run Window Help
```

没有 `Hello`，快捷键也没反应。

### 7.2 根因

运行时日志里明确写着：

```text
org.osgi.framework.BundleException: Could not resolve module: com.example.hello [16]
  Unresolved requirement: Require-Bundle: org.eclipse.core.commands.source; bundle-version="3.12.500"
```

`MANIFEST.MF` 当时写的是：

```text
Require-Bundle: org.eclipse.ui,
 org.eclipse.core.runtime,
 org.eclipse.core.commands.source;bundle-version="3.12.500"
```

**`org.eclipse.core.commands.source` 是源码包，不是运行时 API 包。**

### 7.3 为什么整个插件都不见了

OSGi 的解析是“全有或全无”：

- 只要有一个 `Require-Bundle` 无法满足；
- 整个 `com.example.hello` 就停在未解析状态；
- 它的 `plugin.xml` 就不会被扩展注册表读取；
- 于是视图、菜单、命令、快捷键全部不生效。

所以不是“菜单配置错了”，而是“插件根本没加载”。

### 7.4 为什么代码还能编译

因为 `org.eclipse.ui` 重新导出了 `org.eclipse.jface`，而 `org.eclipse.jface` 又重新导出了 `org.eclipse.core.commands`：

```text
org.eclipse.ui
  └─ reexport org.eclipse.jface
       └─ reexport org.eclipse.core.commands
```

所以 `SayHelloHandler` 能编译，`bin/` 里也有 `.class`。

但这只是“编译期可见”，不代表 `MANIFEST.MF` 里显式写的 `.source` 依赖能解析。

**编译通过 ≠ 运行可用。** 这是 OSGi 开发最重要的直觉之一。

### 7.5 怎么修

删掉：

```text
org.eclipse.core.commands.source
```

最终保留：

```text
Require-Bundle: org.eclipse.ui,
 org.eclipse.core.runtime
```

`org.eclipse.ui` 的传递依赖已经足够让 `SayHelloHandler` 编译和运行。

如果以后想显式声明，正式做法是用：

```text
Import-Package: org.eclipse.core.commands
```

而不是把 `.source` 包加进 `Require-Bundle`。

### 7.6 为什么 PDE 的 “Plug-in Selection” 只显示 `.source`

你当时搜索 `org.eclipse.core.commands`，对话框只列出：

```text
org.eclipse.core.commands.source (3.12.500...)
```

这可能是 PDE 对目标平台/源码包的过滤显示问题。不要因为对话框只显示 `.source` 就选它。

判断依据应该是：

- `plugins/` 下有没有 `org.eclipse.core.commands_*.jar`；
- `configuration/org.eclipse.equinox.simpleconfigurator/bundles.info` 里有没有它；
- 运行时日志有没有 `BundleException`。

本次确认过：

```text
org.eclipse.core.commands,3.12.500.v20251103-0733,plugins/org.eclipse.core.commands_3.12.500.v20251103-0733.jar,4,false
```

运行时 Bundle 是有的，只是对话框没显示。

### 7.7 如何快速定位这类问题

1. 打开运行时 Eclipse 的 `Window > Show View > Error Log`。
2. 或直接看运行时工作空间的：

```text
<runtime-workspace>/.metadata/.log
```

3. 搜索：

```text
!ENTRY com.example.hello
BundleException
Could not resolve
Unresolved requirement
ClassNotFoundException
```

4. 看到 `Unresolved requirement: Require-Bundle: xxx`，就去 `MANIFEST.MF` 删/换对应依赖。

## 八、快捷键为什么从 Ctrl+Alt+H 换成 Ctrl+Shift+Alt+H

Eclipse 的按键方案里：

| 标记 | Windows/Linux | macOS |
|---|---|---|
| `M1` | Ctrl | Command |
| `M2` | Shift | Shift |
| `M3` | Alt | Option |
| `M4` | Command | Control |

`Ctrl+Alt+H` 在 JDT 里是 **Open Call Hierarchy** 的默认快捷键。你自定义的命令和它冲突，平台会把按键交给已有绑定。

所以改成：

```xml
sequence="M1+M2+M3+H"
```

即 **Ctrl+Shift+Alt+H**。

验证方法：

```text
Window > Preferences > General > Keys
```

- 搜索 `Say Hello`，确认绑定；
- 搜索 `Ctrl+Alt+H`，能看到 `Open Call Hierarchy`，就知道冲突来源。

## 九、为什么改完 `plugin.xml` 必须重启运行时

扩展注册表是在 Eclipse 启动时读取 `plugin.xml` 的。

- 改 Java 方法体：Debug 模式下可能热替换；
- 改 `plugin.xml`、`MANIFEST.MF`、`Application.e4xmi`：**必须重启运行时**；
- 改目标平台：也要重启。

所以流程是：

```text
改代码/配置 → 保存 → 关闭第二个 Eclipse → Run As > Eclipse Application
```

不是“点一下 Run 就自动热更新插件结构”。

## 十、两个 Eclipse、两个工作空间

### 10.1 开发 IDE

你写代码的 Eclipse：

- 运行 JDT、PDE、Git（第 3 层工具）；
- 工作空间里是源码项目；
- 负责编译、启动运行时。

### 10.2 运行时 Eclipse

`Run As > Eclipse Application` 打开的第二个窗口：

- 加载目标平台 + 你的插件；
- 有自己的运行时工作空间；
- 通常没有项目，显示 “There are no projects in your workspace” 是正常的；
- 它才是“你的应用”。

### 10.3 本次的路径

- 项目源码：`D:\eclipse-workspace\rcp-learn\com.example.hello`
- 开发 IDE 工作空间：当前显示为 `C:\Users\薰\eclipse-workspace`（项目以链接方式加入）
- 运行时工作空间：`C:\Users\薰\runtime-EclipseApplication`
- 运行时日志：`C:\Users\薰\runtime-EclipseApplication\.metadata\.log`

> 建议以后统一用桌面快捷方式启动开发 IDE，工作空间固定为 `D:\eclipse-workspace\rcp-learn`，减少“项目在 D:、工作空间在 C:”的混乱。
> 运行时工作空间是 PDE 自动建的，不要把自己的源码放进去。

## 十一、Target Platform 与依赖选择

`Target Platform` 是你的插件“编译/运行所依赖的 Bundle 集合”。

- 学习阶段用 **Running Platform**（当前 IDE）最方便；
- 正式项目应建 `.target` 文件，锁定 2026-06 更新站点；
- 选依赖时优先用 **运行时 Bundle**，不要选 `.source`；
- 生产项目更推荐 `Import-Package`，只依赖公开 API；
- `Require-Bundle` 简单直接，但耦合更紧。

本次的教训：

> PDE 对话框里“能搜到的”不一定是你需要的；`.source` 是源码包，不是运行时包。

## 十二、3.x 写法与 e4 写法对照

今天用的是 3.x 扩展点。以后学 e4 时，概念不变，写法变了：

| 3.x | e4 |
|---|---|
| `org.eclipse.ui.commands` | `MCommand`（应用模型） |
| `org.eclipse.ui.handlers` + `AbstractHandler` | `MHandler` + `@Execute` / `@CanExecute` |
| `org.eclipse.ui.menus` | `MMenu` / `MHandledMenuItem` |
| `org.eclipse.ui.bindings` | `MKeyBinding` / `MBindingContext` |
| `HandlerUtil.getActiveShell(event)` | `@Inject` 注入 `MWindow` / `Shell` |
| `plugin.xml` | `Application.e4xmi` / fragment |

为什么先学 3.x：

- 最短路径，能快速看到“命令 → 处理器 → 菜单”的完整闭环；
- 企业老项目大量使用 3.x；
- 现代项目常是 3.x + e4 混合；
- e4 的概念（命令、处理器、Part、上下文）建立在同一套思想上。

## 十三、你应该学会的 8 个概念

- [ ] **扩展点（Extension Point）**：平台开放的插槽。
- [ ] **扩展（Extension）**：你的插件向插槽注册的内容。
- [ ] **命令（Command）**：只定义 ID/名称，不含代码。
- [ ] **处理器（Handler）**：真正执行命令的 Java 类。
- [ ] **菜单贡献（Menu Contribution）**：命令的触发入口。
- [ ] **快捷键绑定（Binding）**：命令的另一个触发入口。
- [ ] **Bundle 解析（Resolution）**：OSGi 检查依赖，全有或全无。
- [ ] **运行时实例（Runtime Eclipse）**：加载目标平台 + 你的插件，不是开发 IDE。

## 十四、常见坑清单

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 把 `.source` 包加进 `Require-Bundle` | Bundle 解析失败，整个插件不加载 | 用运行时 Bundle，或 `Import-Package` |
| `commandId` 三处不一致 | 菜单出现但点击无反应 | commands/handlers/menus 三处 ID 完全一致 |
| 改完 `plugin.xml` 不重启 | 菜单不出现 | 关闭运行时 Eclipse，重新 Run |
| 在开发 IDE 里按快捷键 | 没反应 | 在第二个 Eclipse（运行时）里按 |
| `Ctrl+Alt+H` | 被 JDT 的 Open Call Hierarchy 抢走 | 用 `Ctrl+Shift+Alt+H` |
| 菜单找不到 | 以为没生效 | 看菜单栏最右边，`after=additions` 可能排在 Help 后 |
| Handler 类名/包名错 | 点击报 `ClassNotFoundException` | 检查 `class` 全限定名 |
| 编译通过就以为能跑 | 运行时 Bundle 解析失败 | 看 `.metadata/.log` 的 `BundleException` |
| 把源码/项目放进运行时 workspace | 工作空间混乱 | 运行时 workspace 是 PDE 自动建的，不要放源码 |
| 依赖全选 | 产品臃肿、冲突多 | 只加需要的 Bundle，正式项目用 `.target` |

## 十五、下一步练习

### 15.1 命令启用/禁用

给 handler 加 `enabledWhen`，让命令“只有选中表格行时才可用”：

```xml
<handler
      commandId="com.example.hello.commands.sayHello"
      class="com.example.hello.handlers.SayHelloHandler">
   <enabledWhen>
      <with variable="selection">
         <count value="+"/>
      </with>
   </enabledWhen>
</handler>
```

然后在 `Hello View` 里选中/不选中行，观察菜单是否变灰。

这会让你开始接触 **core expressions**：Eclipse 用表达式判断命令是否可用。

### 15.2 把同一个命令放到工具栏

```xml
<menuContribution
      locationURI="toolbar:org.eclipse.ui.main.toolbar?after=additions">
   <command
         commandId="com.example.hello.commands.sayHello"
         label="Say Hello"
         icon="icons/sample.png"
         style="push">
   </command>
</menuContribution>
```

验证“一个命令、多个触发入口”。

### 15.3 用当前选择做业务

在 handler 里读取当前选择：

```java
IStructuredSelection selection =
        HandlerUtil.getCurrentStructuredSelection(event);
Object first = selection.getFirstElement();
```

如果选中的是任务对象，就弹出任务名称，而不是固定文字。

## 十六、自测题

1. 为什么 `Command` 里没有代码？代码在哪里？
2. 菜单项为什么只写 `commandId`，不直接写 Java 类？
3. 如果 `commands` 里的 ID 是 `A`，`handlers` 里写成 `B`，会发生什么？
4. `org.eclipse.core.commands.source` 为什么会导致整个插件加载失败？
5. 为什么代码能编译，运行时却 `BundleException`？
6. 为什么改完 `plugin.xml` 必须重启运行时？
7. `Ctrl+Alt+H` 为什么没反应？怎么排查？
8. `locationURI="menu:org.eclipse.ui.main.menu?after=additions"` 是什么意思？
9. 第一个 Eclipse 和第二个 Eclipse 分别是什么？
10. 菜单没出现时，应该按什么顺序排查？

参考答案：

1. 命令只是契约；代码在 Handler 的 `execute` 里。
2. 解耦：菜单是触发入口，处理器是实现，通过 ID 绑定。
3. 菜单能找到命令，但找不到处理器；点击无反应或日志报错。
4. `.source` 是源码包，不是运行时 Bundle；OSGi 解析失败，整个 Bundle 不加载。
5. 编译期靠 JFace 的 re-export 能看见类；运行期显式 `Require-Bundle` 的 `.source` 无法解析。
6. 扩展注册表在启动时读取 `plugin.xml`，结构变化不会热加载。
7. JDT 默认把 `Ctrl+Alt+H` 绑定为 Open Call Hierarchy；在 Preferences > Keys 查看冲突，换 sequence。
8. 挂到主菜单栏，位置在 `additions` 分组之后。
9. 第一个是开发 IDE（JDT/PDE），第二个是运行时实例（目标平台 + 你的插件）。
10. 看运行时日志 → 查 Bundle 是否解析 → 查 `plugin.xml` 扩展 → 查 ID 一致性 → 查是否重启 → 查快捷键冲突。

## 十八、最后总结

今天最值得记住的不是“怎么加菜单”，而是这三句话：

1. **命令是契约，处理器是实现，菜单/快捷键只是触发入口。**
2. **OSGi 解析失败，插件的一切扩展都不会存在；先看日志，再看代码。**
3. **编译通过 ≠ 运行可用；开发 IDE ≠ 运行时实例。**

把这三句话记住，后面学 e4、Feature/Product、Tycho 时，遇到问题会少走很多弯路。
