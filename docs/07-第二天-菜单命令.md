# 第二天：给插件加菜单命令

> 目标：30–45 分钟，让运行时 Eclipse 的主菜单出现 `Hello > Say Hello`，点击弹出对话框，并支持快捷键 `Ctrl+Shift+Alt+H`。
> 前置：`com.example.hello` 已经能运行，`Hello View` 能打开，双击表格行能弹出对话框。

## 一、先理解三个角色

Eclipse 的命令体系把“动作”拆成三部分：

```text
菜单 / 工具栏 / 快捷键
        │ 通过 commandId 引用
        ▼
Command（命令：只定义 ID、名称、说明，不含代码）
        │ 通过 commandId 绑定
        ▼
Handler（处理器：真正执行的 Java 代码）
```

为什么要拆开？

- **一个命令可以有多个触发入口**：主菜单、工具栏、右键菜单、快捷键。
- **命令 ID 是契约**：菜单只认 ID，不关心谁实现。
- **处理器可以替换/启用禁用**：同一个命令在不同上下文可以有不同的处理器。
- **便于测试和扩展**：别人可以给你的命令重新绑定处理器。

今天要加的四个扩展点：

| 扩展点 | 作用 |
|---|---|
| `org.eclipse.ui.commands` | 定义命令 |
| `org.eclipse.ui.handlers` | 把命令绑定到处理器类 |
| `org.eclipse.ui.menus` | 把命令挂到菜单/工具栏 |
| `org.eclipse.ui.bindings` | 给命令加快捷键（可选） |

## 二、最终要新增的内容

```text
com.example.hello/
├─ plugin.xml                 新增 4 个 extension
└─ src/com/example/hello/
   └─ handlers/
      └─ SayHelloHandler.java 新增处理器类
```

## 三、定义命令

打开 `com.example.hello/plugin.xml`，切到 `plugin.xml` 源码页（底部 `plugin.xml` 标签），在最后的 `</plugin>` 之前加入：

```xml
   <extension
         point="org.eclipse.ui.commands">
      <command
            id="com.example.hello.commands.sayHello"
            name="Say Hello"
            description="Show a hello message from the command handler.">
      </command>
   </extension>
```

解释：

- `id`：命令的唯一标识，后面菜单、快捷键、处理器都用它。
- `name`：显示名称。
- `description`：说明，会出现在 Preferences > Keys 等地方。
- 这里**没有代码**，只有声明。

> 也可以在 `Extensions` 页用 `Add...` 添加 `org.eclipse.ui.commands`，再填 `id/name/description`。两种方式等价，直接编辑 XML 更容易看清结构。

## 四、新增处理器类

### 4.1 新建类

在 `src` 上右键：

```text
New > Class
```

| 字段 | 填写 |
|---|---|
| Package | `com.example.hello.handlers` |
| Name | `SayHelloHandler` |
| Superclass | `org.eclipse.core.commands.AbstractHandler` |

点 `Finish`。

### 4.2 代码

把类改成：

```java
package com.example.hello.handlers;

import org.eclipse.core.commands.AbstractHandler;
import org.eclipse.core.commands.ExecutionEvent;
import org.eclipse.core.commands.ExecutionException;
import org.eclipse.jface.dialogs.MessageDialog;
import org.eclipse.ui.handlers.HandlerUtil;

public class SayHelloHandler extends AbstractHandler {

    @Override
    public Object execute(ExecutionEvent event) throws ExecutionException {
        MessageDialog.openInformation(
                HandlerUtil.getActiveShell(event),
                "Hello Command",
                "Hello from command handler!");
        return null;
    }
}
```

解释：

- `AbstractHandler`：3.x 命令处理器的基类。
- `execute(ExecutionEvent event)`：命令被触发时调用。
- `HandlerUtil.getActiveShell(event)`：拿到当前活动窗口，作为对话框的父窗口。
- 返回 `null` 表示命令没有返回值（大多数 UI 命令都这样）。

### 4.3 如果报找不到 `org.eclipse.core.commands`

虽然当前依赖链可以通过 `org.eclipse.ui -> org.eclipse.jface -> org.eclipse.core.commands` 传递到，但建议显式声明：

1. 双击 `META-INF/MANIFEST.MF`
2. 切到 `Dependencies` 页
3. `Required Plug-ins` → `Add...`
4. 搜索并添加 `org.eclipse.core.commands`
5. 保存

这样依赖关系更清晰，以后改用 `Import-Package` 也不容易漏。

## 五、把命令绑定到处理器

继续在 `plugin.xml` 的 `</plugin>` 之前加入：

```xml
   <extension
         point="org.eclipse.ui.handlers">
      <handler
            commandId="com.example.hello.commands.sayHello"
            class="com.example.hello.handlers.SayHelloHandler">
      </handler>
   </extension>
```

解释：

- `commandId` 必须和第三步定义的命令 ID 完全一致。
- `class` 是处理器的全限定类名。
- 一个命令可以有多个 handler，通过 `enabledWhen` 等条件选择；今天先保持简单。

## 六、把命令挂到主菜单

继续加入：

```xml
   <extension
         point="org.eclipse.ui.menus">
      <menuContribution
            locationURI="menu:org.eclipse.ui.main.menu?after=additions">
         <menu
               id="com.example.hello.menu.hello"
               label="Hello">
            <command
                  commandId="com.example.hello.commands.sayHello"
                  label="Say Hello"
                  style="push">
            </command>
         </menu>
      </menuContribution>
   </extension>
```

解释：

- `locationURI="menu:org.eclipse.ui.main.menu?after=additions"`：把贡献挂到主菜单栏，位置在 `additions` 之后。
- `<menu id="..." label="Hello">`：创建一个顶级菜单 `Hello`。
- `<command commandId="..." style="push">`：在 `Hello` 菜单里加一个普通菜单项。
- `label` 是菜单项显示文字；`style="push"` 表示普通按钮，不是勾选/单选。

> 注意：`locationURI` 不是文件路径，而是 Eclipse 的“菜单位置 URI”。`menu:` 表示菜单栏，`toolbar:` 表示工具栏。

## 七、加快捷键（可选）

继续加入：

```xml
   <extension
         point="org.eclipse.ui.bindings">
      <key
            commandId="com.example.hello.commands.sayHello"
            schemeId="org.eclipse.ui.defaultAcceleratorConfiguration"
            sequence="M1+M2+M3+H">
      </key>
   </extension>
```

解释：

- `M1` = Ctrl（Windows/Linux），`M2` = Shift，`M3` = Alt，`M4` = Command（macOS）。
- `M1+M2+M3+H` 就是 **Ctrl+Shift+Alt+H**。
- `schemeId` 用默认快捷键方案即可。

> 注意：不要用 `M1+M3+H`（Ctrl+Alt+H）。它在 JDT 里默认绑定到 `Open Call Hierarchy`，会把你的快捷键抢走。`Ctrl+Shift+Alt+H` 一般不会冲突。

## 八、运行并验证

### 8.1 重新启动运行时

如果第二个 Eclipse 还开着，先关闭它，然后在开发 IDE 里：

```text
右键 com.example.hello > Run As > Eclipse Application
```

### 8.2 测试菜单

在第二个 Eclipse 的主菜单栏中，应该出现：

```text
Hello > Say Hello
```

点击 `Say Hello`，应弹出：

```text
Hello from command handler!
```

### 8.3 测试快捷键

在第二个 Eclipse 里按：

```text
Ctrl + Alt + H
```

应弹出同样的对话框。

### 8.4 查看命令注册

在第二个 Eclipse 中：

```text
Window > Preferences > General > Keys
```

搜索 `Say Hello`，应该能看到：

- Command：`Say Hello`
- Binding：`Ctrl+Shift+Alt+H`
- When：默认

这说明命令、处理器、菜单、快捷键四者已经串起来了。

## 九、如果没出现

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 菜单 `Hello` 没出现 | `plugin.xml` 扩展没保存 / 运行时没重启 | 保存 `plugin.xml`，关闭并重新 Run |
| 菜单出现但灰色 | 没有 handler / handler 类名错 | 检查 `org.eclipse.ui.handlers` 的 `class` |
| 点击报 `ClassNotFoundException` | 类没编译 / 包名错 | 检查 `SayHelloHandler` 的包名和类名；看 `.metadata/.log` |
| 点击没反应 | `commandId` 不一致 | 三处 ID 必须完全一致：commands、handlers、menus |
| 快捷键冲突 | 被其他命令占用 | Preferences > Keys 搜索 `Say Hello`，换一个 sequence |
| `Ctrl+Alt+H` 没反应 | JDT 默认把它绑定为 `Open Call Hierarchy` | 改用 `M1+M2+M3+H`（Ctrl+Shift+Alt+H） |
| 菜单在错误位置 | `locationURI` 写错 | 先用 `menu:org.eclipse.ui.main.menu?after=additions` |
| 项目报 `org.eclipse.core.commands` 找不到 | 没加依赖 | MANIFEST > Dependencies 添加 `org.eclipse.core.commands` |

## 十、进阶练习

完成基础版后，可以再试：

### 10.1 改菜单文字

把菜单项 `label="Say Hello"` 改成 `label="打个招呼"`，看运行时菜单是否变化。

### 10.2 加工具栏按钮

再加一个 `menuContribution`：

```xml
   <extension
         point="org.eclipse.ui.menus">
      <menuContribution
            locationURI="toolbar:org.eclipse.ui.main.toolbar?after=additions">
         <command
               commandId="com.example.hello.commands.sayHello"
               label="Say Hello"
               icon="icons/sample.png"
               style="push">
         </command>
      </menuContribution>
   </extension>
```

这样同一个命令会同时出现在菜单和工具栏，验证“一个命令、多个触发入口”。

### 10.3 没有选择时禁用命令（可选，稍难）

给 handler 加 `enabledWhen`：

```xml
      <handler
            commandId="com.example.hello.commands.sayHello"
            class="com.example.hello.handlers.SayHelloHandler">
         <enabledWhen>
            <with variable="selection">
               <count value="+"/>
            </with>
         </enabledWhen>
      </handler>
```

含义：只有当当前选择至少有一个元素时，命令才可用。测试时先在 `Hello View` 里选中一行，再看菜单是否变亮。

## 十一、今天要理解的 5 个问题

1. 命令（Command）里有代码吗？代码在哪里？
2. 为什么菜单只写 `commandId`，不直接写 Java 类？
3. 一个命令能不能同时挂到菜单、工具栏、快捷键？怎么做到？
4. `M1+M2+M3+H` 分别代表什么键？
5. 如果两个插件定义了同一个 `commandId`，会发生什么？

参考答案：

1. 没有；代码在 Handler 的 `execute` 里。
2. 解耦：菜单是“触发入口”，处理器是“实现”，通过 ID 绑定。
3. 可以；多个 `menuContribution`/`key` 引用同一个 `commandId`。
4. `M1`=Ctrl，`M2`=Shift，`M3`=Alt，`M4`=Command（macOS）。
5. 后加载/优先级高的贡献可能覆盖或冲突；命令 ID 应使用命名空间，避免重复。

## 十三、和 e4 的对应关系

今天用的是 3.x 扩展点。到第 6 周学 e4 时，你会看到同一套思想换了写法：

| 3.x | e4 |
|---|---|
| `org.eclipse.ui.commands` | `MCommand`（应用模型） |
| `org.eclipse.ui.handlers` + `AbstractHandler` | `MHandler` + `@Execute` / `@CanExecute` |
| `org.eclipse.ui.menus` | `MMenu` / `MHandledMenuItem`（应用模型） |
| `org.eclipse.ui.bindings` | `MKeyBinding` / `MBindingContext` |
| `HandlerUtil.getActiveShell(event)` | `@Inject` 注入 `MWindow` / `Shell` |

概念没有变：**命令是契约，处理器是实现，菜单/快捷键是触发入口。**
