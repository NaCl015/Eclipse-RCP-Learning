## 二、为什么选 Eclipse 2026-06，而不是 2026-09

Eclipse 每个季度版本对 JDK 的要求不同：

| Eclipse 版本 | IDE 运行要求 | 是否适合本机 |
|---|---|---|
| 2026-09（4.41） | Java 25 | 不适合，需要再装 JDK 25 |
| **2026-06（4.40）** | **Java 21** | **适合，本次选择** |
| 2026-03（4.39） | Java 21 | 可选 |
| 2024-03（4.31） | Java 17 | 公司要求 Java 17 时使用 |

既然目标是“统一使用 Java 21”，就选择 2026-06。这样 IDE、编译、运行、Tycho 构建都在同一个 JDK 21 上，排错时少一个变量。

## 七、配置 eclipse.ini

### 7.1 默认配置

Eclipse 2026-06 的 zip 自带 `eclipse.ini`，其中已经包含：

```ini
-vm
plugins/org.eclipse.justj.openjdk.hotspot.jre.full.win32.x86_64_21.0.11.v20260515-1531/jre/bin
```

也就是说，它默认使用安装包内置的 Java 21.0.11 JRE。

### 7.2 改成外部 JDK 21

为了让 IDE、Maven、Tycho 使用同一套 JDK，本次改成 `D:\Java21`：

```ini
-vm
D:\Java21\bin\javaw.exe
```

完整的关键部分如下：

```ini
-startup
plugins/org.eclipse.equinox.launcher_1.7.100.v20251111-0406.jar
--launcher.library
plugins/org.eclipse.equinox.launcher.win32.win32.x86_64_1.3.0.v20260203-2149
-product
org.eclipse.epp.package.rcp.product
-showsplash
org.eclipse.epp.package.common
--launcher.defaultAction
openFile
--launcher.appendVmargs
-vm
D:\Java21\bin\javaw.exe
-vmargs
-Xmx4g
-Dfile.encoding=UTF-8
-XX:CompileCommand=quiet
-Dosgi.requiredJavaVersion=21
-Dosgi.instance.area.default=@user.home/eclipse-workspace
-Dorg.eclipse.swt.graphics.Resource.reportNonDisposed=true
-XX:+UseG1GC
-XX:+UseStringDeduplication
--add-modules=ALL-SYSTEM
```

### 7.3 每一行的作用

| 配置 | 作用 |
|---|---|
| `-startup` | 指定 Equinox launcher jar |
| `--launcher.library` | 指定平台相关的 launcher 库 |
| `-product` | 指定启动的 product ID |
| `-vm` | 指定运行 Eclipse 的 JVM |
| `-vmargs` | 后面的参数传给 JVM |
| `-Xmx4g` | 最大堆 4 GB；16 GB 内存够用 |
| `-Dfile.encoding=UTF-8` | 统一编码，减少中文乱码 |
| `-Dosgi.requiredJavaVersion=21` | 要求 Java 21 |
| `-XX:+UseG1GC` | 使用 G1 垃圾回收器 |
| `--add-modules=ALL-SYSTEM` | 加载需要的 JDK 模块 |

### 7.4 三个容易踩的坑

1. **`-vm` 必须放在 `-vmargs` 前面**，否则会被当成 JVM 参数。
2. **路径必须单独一行**，不能写 `-vm D:\Java21\bin\javaw.exe`。
3. **用 `javaw.exe` 而不是 `java.exe`**，否则启动时会多一个控制台窗口。

## 九、Maven 配置

### 9.1 为什么 RCP 还需要 Maven

Eclipse PDE 可以在 IDE 里点按钮构建，但正式项目通常需要：

- 命令行无 GUI 构建；
- CI（GitHub Actions / Jenkins）自动构建；
- 可复现的 p2 依赖解析。

这就是 Tycho 的作用。Tycho 是 Maven 插件，不需要单独安装，写在 `pom.xml` 里即可。

### 9.2 settings.xml

本次创建了 `C:\Users\薰\.m2\settings.xml`：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<settings xmlns="http://maven.apache.org/SETTINGS/1.2.0"
          xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
          xsi:schemaLocation="http://maven.apache.org/SETTINGS/1.2.0 https://maven.apache.org/xsd/settings-1.2.0.xsd">
  <!-- 保留默认本地仓库，避免已有项目重复下载 -->
  <!-- <localRepository>D:\Maven\repository</localRepository> -->

  <mirrors>
    <mirror>
      <id>aliyun</id>
      <name>Aliyun Public</name>
      <url>https://maven.aliyun.com/repository/public</url>
      <mirrorOf>central</mirrorOf>
    </mirror>
  </mirrors>
</settings>
```

说明：

- 只加速 Maven Central，不改变本地仓库位置；
- Tycho 的依赖主要来自 p2 更新站点，Maven 镜像不覆盖 p2；
- 如果以后想统一本地仓库，取消 `localRepository` 注释即可。

### 9.3 toolchains.xml

`C:\Users\薰\.m2\toolchains.xml`：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<toolchains>
  <toolchain>
    <type>jdk</type>
    <provides><version>21</version></provides>
    <configuration><jdkHome>D:\Java21</jdkHome></configuration>
  </toolchain>
  <toolchain>
    <type>jdk</type>
    <provides><version>17</version></provides>
    <configuration><jdkHome>D:\Java17\jdk-17.0.10</jdkHome></configuration>
  </toolchain>
</toolchains>
```

Tycho 构建多版本目标平台时，会从 toolchains 里选择对应 JDK。

### 9.4 mvn21.cmd

本机的系统级 `JAVA_HOME` 仍是 JDK 17，而 Tycho 构建 2026-06 平台需要 Java 21。为避免每次手动改环境变量，创建 `D:\tools\mvn21.cmd`：

```bat

setlocal
set "JAVA_HOME=D:\Java21"
call "D:\Maven\apache-maven-3.9.8\bin\mvn.cmd" %*
endlocal
```

使用：

```powershell

D:\tools\mvn21.cmd clean verify
```

## 十、环境变量

### 10.1 本次设置

| 变量 | 级别 | 值 | 说明 |
|---|---|---|---|
| `JAVA_HOME` | 用户级 | `D:\Java21` | 新开的终端/Maven 默认使用 21 |
| `JAVA_HOME` | 系统级 | `D:\Java17\jdk-17.0.10` | 未改，避免影响旧项目 |
| `PATH` | 用户级 | 追加 `D:\tools` | 方便调用 `mvn21`、启动脚本 |
| `HOME` | 用户级 | `C:\Users\薰` | 让 EGit 与 Git for Windows 使用同一套全局配置 |

设置命令（不需要管理员）：

```powershell
[Environment]::SetEnvironmentVariable('JAVA_HOME', 'D:\Java21', 'User')

$userPath = [Environment]::GetEnvironmentVariable('Path', 'User')
if ($userPath -notmatch 'D:\\tools') {
    [Environment]::SetEnvironmentVariable('Path', "$userPath;D:\tools", 'User')
}

# 让 EGit 与 Git for Windows 使用同一个 HOME
[Environment]::SetEnvironmentVariable('HOME', $env:USERPROFILE, 'User')
```

### 10.2 为什么直接敲 `java` 可能还是 17

Windows 的 PATH 顺序是“系统 PATH + 用户 PATH”。本机系统 PATH 里靠前的位置有：

```text
C:\Program Files\Common Files\Oracle\Java\javapath
D:\Java17\jdk-17.0.10\bin
```

用户 PATH 里的 `D:\Java21\bin` 即使加了，也排在后面，所以：

```powershell
where.exe java
```

可能仍然显示 Oracle javapath 和 JDK 17。

这不影响 RCP 开发，因为：

- Eclipse 用 `eclipse.ini` 的 `-vm` 固定 JDK 21；
- Maven 用 `mvn21.cmd` 固定 JDK 21；
- 需要验证时用绝对路径：

```powershell
D:\Java21\bin\java -version
```

如果确实想让新终端默认使用 21，需要管理员权限，把 `D:\Java21\bin` 放到系统 PATH 的最前面，或者把 Oracle javapath 往后移。建议先不要改，等熟悉环境后再动。

## 十三、第一次启动后的 5 件事

按顺序做，避免后面踩坑：

1. **设置 UTF-8**
   `Window > Preferences > General > Workspace > Text file encoding = UTF-8`

2. **确认 JDK**
   `Window > Preferences > Java > Installed JREs`
   - 添加 `D:\Java21`
   - 添加 `D:\Java17\jdk-17.0.10`
   - 默认勾选 JDK 21

## 十五、常见问题

### 15.1 Eclipse 启动报 `Java was started but returned exit code=13`

原因：`-vm` 路径错误，或指向了不存在的 `javaw.exe`。

检查：

```powershell
Test-Path 'D:\Java21\bin\javaw.exe'
```

并确认 `eclipse.ini` 中：

```ini
-vm
D:\Java21\bin\javaw.exe
```

### 15.2 启动报 `JVM terminated. Exit code=1`

常见原因：

- `-vm` 写在了 `-vmargs` 后面；
- `-vm` 和路径写在了同一行；
- `-Xmx4g` 超过了可用内存。

### 15.3 新终端 `java -version` 还是 17

这是本机 PATH 顺序导致的，不影响 RCP。用：

```powershell
D:\Java21\bin\java -version
D:\tools\mvn21.cmd -v
```

### 15.4 Eclipse 启动很慢

- 第一次启动需要初始化插件，正常；
- 把 `D:\eclipse`、`D:\eclipse-workspace` 加入 Windows Defender 排除项；
- 关闭不用的插件/视图；
- 内存上限保持 `-Xmx4g`，不要盲目调到 8g 以上。

### 15.5 下载中断

重新执行同一条 `curl` 命令即可，`-C -` 会从断点继续。如果文件已损坏，删除后重下，并校验 SHA256。

### 15.6 EGit 提示 `HOME is not set`

首次启动可能在 `.metadata/.log` 看到：

```text
Warning: The environment variable HOME is not set.
```

这是 EGit 找不到 `HOME`，会退回使用用户目录。本次已设置用户级 `HOME=C:\Users\薰`，重启 Eclipse 后不再出现。也可以在：

```text
Team > Git > Confirmations and Warnings
```

关闭该警告。

### 15.7 中文乱码

- 工作空间编码设为 UTF-8；
- `eclipse.ini` 已有 `-Dfile.encoding=UTF-8`；
- 产品启动参数也加上 `-Dfile.encoding=UTF-8`；
- 不要用 GBK 保存 Java 源文件。
